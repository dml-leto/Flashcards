# **Описание проекта: Сервис карточек для изучения языков (Flashcards)**

Данный документ является технической и доменной спецификацией сервиса для изучения иностранных языков и грамматических конструкций с помощью интерактивных карточек. Проект разрабатывается как обучающий pet-проект с полным соблюдением стандартов Senior Java/Kotlin Backend разработки и архитектурных паттернов enterprise-уровня.

## **1\. Суть и цели проекта**

Проект представляет собой веб\-сервис для интенсивного заучивания иностранных слов, сложной грамматики, отделяемых приставок и форм слов. Основные цели:

> * **Личная польза:** Ежедневное использование 4 членами семьи с удобным вводом доп. полей и адаптивной тренировкой.  
> * **Senior Interview Signal:** Практическая отработка сложных инженерных тем (PostgreSQL JSONB, Concurrent Batch Processing, Multi-tenant Data Isolation, Model Context Protocol, Transactional Outbox, Testcontainers).

## **2\. Зафиксированная модель домена (предварительно)**

Модель данных строится вокруг понятий структурированного хранения и сессий обучения:

| Сущность | Описание и назначение   |
| :---- | :---- |
| **User (Owner)** | Аккаунт пользователя (owner\_id). В MVP — 4 преднастроенных семейных аккаунта. В будущем — ролевая модель TEACHER / STUDENT. |
| **Folder** | Папка для группировки наборов карточек. Поддерживает вложенность и жестко привязана к owner\_id. |
| **Deck (Набор)** | Семантический сет карточек конкретной темы или урока. |
| **Flashcard** | Карточка. Содержит front\_text (слово/фраза), back\_text (перевод) и attributes (JSONB: формы, приставки, примеры предложений). |
| **Learning Session** | Активная сессия тренировки. Управляет состоянием и батчами по 10 карточек. |
| **Card Progress** | Статистика успеваемости по карточке: число попыток, ошибок, дата последнего повторения, уровень освоения. |

## **3\. Механика режима обучения (Learning Engine) (предварительно)**

Сессия обучения строится как двухстадийный адаптивный процесс:

> 1. **Конфигурация сессии:** Выбор направления (Слово → Перевод или Перевод → Слово). По умолчанию показывается лицевая сторона.  
> 2. **Стадия 1 — Multiple Choice (Выбор из 4 вариантов):**  
   * Выдаётся батч из 10 карточек.  
   * Для каждой карточки генерируется 3 актуальных дистрактора из того же сета или папки.  
   * После ответа открывается правильный ответ и все дополнительные поля карточки (примеры, приставки, формы).  
> 3. **Ротация и обработка ошибок:**  
   * Если все 10 карточек отвечены без ошибок, они считаются усвоенными в сессии, берется следующий батч из 10 новых карточек.  
   * Если допущены ошибки, ошибочные карточки переходят в следующий батч, а оставшиеся слоты добираются новыми словами до 10\.  
> 4. **Стадия 2 — Writing Mode (Письменный ввод):**  
   * Активируется при выборе режима с написанием.  
   * Слова, успешно пройденные в стадии выбора вариантов (10–15 карточек), начинают появляться в режиме письменного ввода.  
   * Показывается перевод (обратная сторона), и пользователь должен вручную ввести исходное слово.

## **4\. Структура модулей приложения (еще не утверждено)**

Сборка и компилятор строго изолируют границы модулей с помощью Kotlin Explicit API (explicitApi() \+ internal):

> * **card-api:** Интерфейсы use case'ов (driving ports), команды, DTO, Value Objects. *Строго 0 зависимостей от фреймворков (без Spring, JPA, Jackson).*  
> * **card-core:** Доменная логика, entities, Learning Engine state machine, репозитории, Spring-конфигурация. *Всё внутреннее содержимое помечено internal.*  
> * **card-web:** REST API контроллеры, Spring Security (JWT/Session), Swagger.  
> * **card-mcp:** MCP Server (JSON-RPC over HTTP/SSE), адаптер для работы с LLM-агентами.  
> * **card-bootstrap:** Composition Root, main(), @SpringBootApplication, application.yml.

## **5\. Технологический стек  (еще не утверждено)**

> * **Языки и фреймворк:** Kotlin (актуальная стабильная версия), Java 25+, Spring Boot 4.x, Gradle 9.x (Kotlin DSL).  
> * **База данных:** PostgreSQL (с использованием JSONB колонок и GIN-индексов), Flyway для миграций.  
> * **Безопасность:** Spring Security \+ JWT / Cookie-Session (Multi-tenant isolation по owner\_id).  
> * **Тестирование:** Testcontainers (PostgreSQL), JUnit 5, AssertJ, ArchUnit.  
> * **Кэширование и очереди (MVP):** Внутреннее кэширование, PostgreSQL Transactional Outbox \+ SKIP LOCKED.

## **6\. Принятые и отвергнутые решения**

| Решение | Статус | Обоснование   |
| :---- | :---- | :---- |
| **PostgreSQL \+ JSONB** | **обсудить** | Полиморфные поля карточки идеально хранятся в JSONB. Низкие расходы RAM (100–150 MB) по сравнению с MongoDB. |
| **Spring Security Auth (4 аккаунта)** | **Принято** | Быстрый старт. В БД закладывается owner\_id для масштабирования в публичный сервис без переработки домена. |
| **Иерархия Учитель / Ученик** | **не в MVP** | Вынесено в Post-MVP (Эпик CARD-6), чтобы сократить Time-to-Market первой версии. |
| **Kafka на старте (PET-1...3)** | **не в MVP** | Заменено на PostgreSQL Outbox \+ SKIP LOCKED. Kafka подключается в Эпике CARD-4 под асинхронный LLM pipeline. |
