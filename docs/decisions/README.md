# Решения

Здесь фиксируются принятые решения: архитектурные (ADR), продуктовые и процессные.
Документ решения объясняет только **почему** решили так. Действующие правила живут в [`CLAUDE.md`](../../CLAUDE.md),
а не здесь. Этот файл — индекс: краткое описание каждого решения и ссылка на документ.

## Правила
- Одно решение = один файл `fc-<N>-<slug>.md`, где `FC-<N>` — issue на GitHub, в рамках которого принято решение.
  Для архитектурных решений после ID добавляется `adr`: `fc-<N>-adr-<slug>.md`. Slug — на английском, kebab-case.
- Заголовок документа начинается с ID: `# FC-<N> · ADR: Название` или `# FC-<N> · Название`.
- Документ короткий: несколько предложений — контекст, что решили и почему. Разделы добавляются, только если без них
  непонятно (например, отвергнутые варианты, которые иначе предложат снова).
- Принятое решение не редактируется, кроме строки статуса. Статусы: `proposed`, `accepted`, `deprecated`,
  `superseded by FC-<M>`; частичная замена — `accepted, уточнено FC-<M>`. Новое решение ссылается на заменённое.
- Если решение меняет правило, `CLAUDE.md` правится в том же PR.
- Добавить или обновить строку в индексе — пункт DoD задачи, в рамках которой принято решение.
