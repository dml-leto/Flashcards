# Решения

Здесь фиксируются принятые решения: архитектурные (ADR), продуктовые и процессные.
Этот файл — индекс: краткое описание каждого решения и ссылка на документ с подробностями (контекст, варианты, trade-offs).

## Правила
- Одно решение = один файл `fc-<N>-<slug>.md`, где `FC-<N>` — issue на GitHub, в рамках которого принято решение.
  Для архитектурных решений после ID добавляется `adr`: `fc-<N>-adr-<slug>.md`. Slug — на английском, kebab-case.
- Заголовок документа начинается с ID: `# FC-<N> · ADR: Название` или `# FC-<N> · Название`.
- Принятое решение не переписывается. Если оно меняется, пишется новый документ со статусом `Supersedes FC-<N>`,
  а у старого статус меняется на `Superseded by FC-<M>`. Порядок принятия виден по дате в индексе.
- Добавить или обновить строку в индексе — пункт DoD задачи, в рамках которой принято решение.

## Шаблон ADR

```markdown
# FC-N · ADR: Заголовок

- **Статус:** Proposed | Accepted | Superseded by FC-M
- **Дата:** YYYY-MM-DD
- **Issue:** FC-N

## Контекст
Какую проблему решаем, какие есть ограничения. Если было предварительное обсуждение — его саммари.

## Решение
Что выбрали, конкретно.

## Рассмотренные альтернативы
Вариант: почему не он.

## Последствия
Что станет проще, что сложнее, какие новые обязательства появляются.
```

Формат — облегчённый [MADR](https://adr.github.io/madr/) (Michael Nygard).
