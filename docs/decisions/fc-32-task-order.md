# FC-32 · Порядок задач через «План» milestone

- **Статус:** Accepted
- **Дата:** 2026-10-01
- **Issue:** FC-32
- **Уточняет:** FC-1 (правило выбора следующей задачи и поток статусов)

## Контекст
По FC-1 следующей задачей считалась задача «с наивысшим приоритетом среди незаблокированных».
Согласованный порядок этапа 01 (FC-15 → FC-5 → …) жил только в переписке. Новая сессия применила правило
по приоритету и выбрала FC-5 (🔴) вместо FC-15 (🟡). Вдобавок в описании milestone 01 стояла устаревшая строка
«Первым решается FC-5». Выбор следующей задачи оказался зависим от того, какой контекст прочитала сессия.

## Решение
- Порядок работы хранится в описании milestone: строка `План: FC-a → FC-b → …` сразу после `Зависит от: …`.
  Порядок milestones задают их номера.
- Следующая задача — первая незакрытая в `План:` самого раннего открытого milestone. Сессия её не выбирает и не переставляет.
- Если Claude считает порядок неверным, он говорит об этом; `План:` меняется только после «да» пользователя.
- Приоритет и Size используются при планировании (чтобы составить `План:`), а не для выбора следующей задачи.
- Workflows доски дополнены: `Auto-close issue` (статус `Done` закрывает issue) и `Item reopened`.
  Перевести задачу в `Done` можно закрытием issue или переносом карточки — одно синхронизирует другое.

## Рассмотренные альтернативы
- **Числовое поле «Очередь» на доске:** ещё одно поле, которое надо поддерживать вручную и которое легко рассинхронизировать.
- **Отдельный файл плана в `docs/`:** каждое изменение порядка требовало бы PR, а план — живая информация трекера.

## Последствия
- Ответ на «что дальше» — одна строка в трекере, одинаковая для любой сессии.
- Claude обязан вписывать новые задачи текущего этапа в `План:` и согласовывать `План:` следующего этапа после grooming.
